# P5 · 首页（含长度硬性要求）

> 原文摘自 Issue #1（UI 重构需求），按阶段拆分；原文字句不改。与 00_INDEX.md 冲突时以 00_INDEX.md 为准。

七、首页——必须彻底重新布局
首页目标不是“展示所有配置”。
首页只回答三个问题：
系统现在是否正常？
今天发生了什么？
我下一步最可能进入哪里？
首页不允许出现：
API 地址；
API Key；
大段关键词输入框；
Attention 参数；
上传配置；
Debug 日志；
模型详细参数；
高级设置；
一大堆 switch；
一长串后台配置。
这些内容必须移到其他页面。

首页结构
首页从上到下只保留：
A. 大标题
左上：
通知
大约 32sp。
右上可以用非常轻量的小状态：
● 正在运行
或：
今日
9月26日
不要做传统 Toolbar。

B. 系统状态
不要再做一整个大 Card。
可以像一张横向小纸条：
通知筛选服务正在运行
左侧一个绿色小状态点。
右侧一个小箭头/设置入口。
状态必须优先读取现有真实服务状态，不要硬编码“正在运行”。

C. “今日概览”纸张区域
这是首页视觉重点之一。
不使用传统统计 Card。
做成一张像被放在桌面上的纸。
可以采用：
白色纸张底板
+
轻微阴影
+
顶部小标题
+
4 个统计数字
文案：
今日概览
统计使用现有真实通知日志：
今日通知
重要
稍后
已过滤
不要写死假数据。
纸张可以有极轻微的旋转，例如：
-1°
但不能影响阅读。

D. 四个文件夹入口
首页下半部分是：
2 × 2 文件夹网格
四个入口固定为：
重要消息
稍后处理
已过滤
通知记录
每一个必须真的做成“文件夹”。
严禁做成普通 CardView + icon。


十五、首页长度硬性要求
在普通约：
6.1～6.7 英寸手机
上，首页主体应该基本可以在：
1 屏～1.3 屏
内完成主要浏览。
用户第一眼应同时感知到：
通知
系统状态
今日概览
至少大部分文件夹入口
底部导航
绝对不能再出现首页连续向下滚动很多屏。
