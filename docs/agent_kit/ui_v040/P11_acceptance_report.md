# P11 · 最终验收标准与回复格式

> 原文摘自 Issue #1（UI 重构需求），按阶段拆分；原文字句不改。与 00_INDEX.md 冲突时以 00_INDEX.md 为准。

二十四、最终验收标准
只有同时满足以下条件，才算本轮完成。
结构
首页 / 消息 / 智能判断 / 我的四个页面明确分开
底部导航固定存在
首页不再展示全部高级配置
首页不再是多屏超长 Dashboard
首页
有“通知”大标题
有真实运行状态
有“今日概览”
有 2×2 文件夹
四个文件夹分别为重要消息、稍后处理、已过滤、通知记录
文件夹不是普通 Card
文件夹至少有 tab、背板、纸张、前板等结构
点击文件夹可进入对应消息分类
消息
能看到真实通知日志
支持全部 / 重要 / 稍后 / 已过滤筛选
消息使用纸条 / 气泡式视觉
不重新堆回首页
智能判断
使用明显的“白纸 + 彩色便签 + 立体图钉”视觉
模型配置可进入 ModelSettingsActivity
Attention 可进入 AttentionActivity
不伪造不存在的模型功能
我的
收纳权限和低频设置
使用引导可重新打开 OnboardingActivity
页面不过度拥挤
视觉
暖白网格纸背景
大标题
柔和彩色文件夹
真实层叠纸张感
立体图钉
轻阴影
底部悬浮导航
页面有足够留白
不出现蓝紫霓虹科技 Dashboard 风
工程
不引入 Compose
不引入重型 UI 框架
不破坏现有业务核心
不修改 sender/tests/docs
AndroidManifest 正确
Gradle 编译通过


二十六、最终回复格式
全部开发、编译和自检完成以后再回复我。
最终回复只需要告诉我：
1. 本次实际修改/新增了哪些文件
2. 四个页面分别完成了什么
3. 文件夹组件是如何实现的
4. 便签/图钉组件是如何实现的
5. 原 MainActivity 功能分别迁移到了哪里
6. 哪些地方继续复用了原有真实数据和逻辑
7. 是否运行了 Gradle 编译
8. 最终编译是否成功
9. 是否存在仍未实现但保留入口的功能
不要在开发前先回复我“我准备这样做”。
不要把任务拆成 Phase 1、Phase 2 然后本轮只做 Phase 1。
不要要求我再次提供参考图细节。
不要因为某一个视觉细节拿不准就停下来问我。
本轮目标就是：
一次性把当前“所有东西堆在首页”的版本，重构成一个真正具有四页信息架构、文件夹入口、纸质便签、立体图钉、彩色消息气泡和悬浮底部导航的完整 Android UI，并保证原有业务能力可继续使用、项目能够正常编译。
