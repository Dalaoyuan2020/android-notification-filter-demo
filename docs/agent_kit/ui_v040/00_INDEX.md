# 00 · UI v0.4.0 重构工具包：路由与规则（每次会话第一个读）

> 目的：Issue #1 的 UI 需求有 1,200 多行，一次全部塞进上下文会把 agent 撑爆、效果变差。这里拆成**按阶段、按需加载**的小文件。
> **每次会话只读 3 个文件**：本文件 → `STATE.md` → 当前阶段文件（外加 `01_context_min.md`，它很短）。**不要打开 Issue #1 原文，也不要一次读多个阶段文件。**

## 与原文"不要拆 Phase"的关系（重要）
原文要求"不要把任务拆成 Phase 1、Phase 2 然后本轮只做 Phase 1"。这里的分阶段**只是为了按需加载上下文**，不是分批交付：**要一路做到 P11**，每个阶段编译通过就接着做下一个；只有上下文快满时才停，并在 STATE.md 写清楚停在哪，下一个会话接着做。不要停下来问"要不要继续"。

参考图在 `refs/`，哪个阶段看哪张见 `refs/README.md`。

## 每个阶段的固定流程
1. 读本文件 + `STATE.md` + `01_context_min.md` + 当前阶段文件
2. 只改该阶段范围内的代码；需要前面阶段的组件时，读代码本身，不要重读前面阶段的需求文件
3. 编译自检：`.\gradlew.bat :filter:assembleDebug :filter:lintDebug` + 纯 Java 测试；编译不过就自己修，不要带着编译错误进下一阶段
4. `git commit -m "ui-v040: Pn <一句话>"`
5. 在 `STATE.md` 追加一行：阶段、完成内容、新增或修改的文件、遗留问题
6. 上下文还有余量就继续下一阶段；快满了就停下，下一个会话从 `STATE.md` 接着做

## 全局规则（每个阶段都适用）
- 只改 `filter/` 模块的 UI 与配置；不改 `sender/`、`tests/`（P0 可以加测试）、核心算法
- Java + 原生 View；**不引入 Compose，不引入大型第三方 UI 库**
- 新文件名、目录名一律英文小写 + 下划线
- 不写假数据、假消息；没有数据时显示空状态
- 不内置任何 key；key 继续用 Android Keystore 加密存储

### 不要再犯的问题（原文）
十七、不要再犯以下问题
以下内容属于本轮硬性禁止项：
1. 不要首页什么都有。
2. 不要所有模块都做成普通圆角 CardView。
3. 不要文件夹只做成一个矩形加 folder icon。
4. 不要便签只是一个圆角矩形加圆点。
5. 不要大量蓝紫渐变科技风。
6. 不要黑色背景。
7. 不要把所有功能写成表单。
8. 不要为了 UI 重构破坏真实数据逻辑。
9. 不要出现大量假数字和假消息。
10. 不要删除原有功能。
11. 不要把四个页面做成四个超长页面。
12. 不要引入 Compose。
13. 不要引入重型第三方组件库。
14. 不要做到一半告诉我“下一阶段再做视觉细化”。
15. 不要只给我线框图。
16. 不要只写 TODO。
17. 不要让我再次确认颜色、圆角、间距。
请直接根据本提示词完成。

### 执行方式（原文）
二十三、执行方式
请按下面方式直接执行，不要停在中间。
第一步
阅读：
filter/src/main/java/com/example/notificationdemo/filter/
内现有 Activity 和相关类。
先确定：
MainActivity 当前真实结构；
通知日志来自哪里；
重要/稍后/过滤分类字段来自哪里；
服务状态如何读取；
ModelSettingsActivity 如何打开；
AttentionActivity 如何打开；
OnboardingActivity 如何打开；
目前设置项如何保存。
第二步
直接进行 UI 重构。
不要因为与我描述略有差异就停止。
只要不改变业务语义，自行适配现有代码。
第三步
完成：
首页
消息
智能判断
我的
底部导航
文件夹组件
便签组件
消息卡片
原功能迁移
第四步
编译项目。
至少执行类似：
gradlew.bat :filter:assembleDebug
或根据真实 Gradle module 配置执行正确构建命令。
如果编译报错：
自行定位并继续修改，直到成功。

第五步

第六步

二十五、视觉优先级
如果某些细节无法同时做到，请按照以下优先级判断：
