# P9b · 首次启动动画引导：交互、动画、状态、验收

> **范围说明（吕博 2026-09-26 确认）**：首次启动引导做成**动画式手势引导的教程**，用动画演示"怎么用这些功能"（例如手指滑动划掉通知、点开、查看概率变化、进入设置），**有界面、能跑通就行**；原文里更细的动画节奏和打磨**放到后续版本**，本轮不要在这里耗太多时间。OnboardingActivity 不在 main 分支的，**直接按这个范围新做，不用等队友的代码**。

> 原文摘自 Issue #1（UI 重构需求），按阶段拆分；原文字句不改。与 00_INDEX.md 冲突时以 00_INDEX.md 为准。

4. 引导交互方式
推荐底部结构：
跳过                     下一步 →
最后一页：
开始使用
中间放：
● ○ ○ ○
形式的页面进度。
但进度点也尽量做得有一点纸张设计感。
可以使用：
当前页：黑色短胶囊
其他页：浅灰小圆点
不需要使用第三方 ViewPager 库。
如果当前项目已有 ViewPager 可直接复用；
如果没有，可以使用：
FrameLayout
+
页面状态 index
+
自己切换 View
实现。

5. 支持左右滑动
如果不会显著增加复杂度，引导页应支持：
左滑 → 下一页
右滑 → 上一页
同时保留：
下一步
按钮。
可以使用：
GestureDetector
或基础 touch 手势检测。
滑动距离达到合理阈值后再切换。
不要轻微碰一下就换页。
如果现有结构实现左右滑会显著增加不稳定性：
按钮切换优先，动画完整性优先。

6. 页面切换动画
Onboarding 页与页之间不要硬切。
下一页：
当前内容：
translationX 0 → -24dp
alpha 1 → 0

下一页：
translationX 24dp → 0
alpha 0 → 1
推荐时长：
220～320ms
上一页方向反过来。
动画过程中防止用户连续快速点击导致状态错乱。

7. 动画节奏
所有动画遵循：
快
清晰
不拖沓
单个小动画：
150～350ms
页面进入组合动画：
600～1200ms
页面不能让用户等动画结束才能点击：
下一步
如果用户点击下一步，应当直接取消 / 结束当前动画并进入下一幕。

8. 首次启动状态保存
必须正确保存首次启动状态。
可以沿用项目当前已经存在的 SharedPreferences 逻辑。
如果需要完善，使用类似：
onboarding_completed = true
不要使用：
用户只打开过 OnboardingActivity 就直接标记完成
应当在：
点击“开始使用”
或：
点击“跳过”
后才真正写入完成状态。
因此：
第一次启动
onboarding_completed = false
↓
打开 OnboardingActivity
完成之后
onboarding_completed = true
↓
后续启动直接 MainActivity

9. “跳过”逻辑
前三页右上角或底部提供：
跳过
点击跳过后：
保存 onboarding_completed = true
↓
进入 MainActivity
最后一页不再显示“跳过”。
改为：
开始使用

10. 从“我的”重新查看引导
用户进入：
我的
→ 使用引导
时：
必须完整重新播放四幕动画。
但是：
不要重新修改首次启动标记
也就是说它只是“重新查看教程”。
用户退出教程后仍然正常回到 App。
如果从“我的”进入引导，可以让：
跳过
变成：
关闭
最后一页：
返回应用
这样语义更准确。

11. 不要依赖外部图片
这套引导优先全部通过：
Android View
Drawable
Shape
TextView
自定义简单 Canvas
实现。
不依赖网络资源。
不要加载 GIF。
不要为了动画下载素材。
这样保证：
离线也可以正常显示
并与首页真实组件统一。

12. 最重要的一点：引导中的元素尽量复用正式 UI
不要给 onboarding 单独开发一套完全不同的视觉组件。
比如：
文件夹
消息纸条
状态标签
便签
应尽可能复用：
buildFolderCard(...)
buildMessageBubble(...)
buildPinnedNote(...)
或对应 UI helper。
这样首次教程中用户看到的东西，与真正进入 App 后看到的是一致的。
特别是第三幕的：
重要消息
稍后处理
已过滤
三个文件夹，
应与首页正式文件夹使用同一套设计语言。

13. 动画引导不能影响正式业务
OnboardingActivity 只能负责：
产品介绍
使用说明
首次启动状态
不要在引导中：
请求大量权限；
修改筛选参数；
修改模型设置；
自动打开通知权限页；
写入假的通知数据；
启动测试消息。
权限等真实操作进入正式 App 后再完成。

14. 如果用户开启“减少动画”
如果实现成本合理，可以尊重 Android：
Animator duration scale
或系统减少动画行为。
至少需要保证：
即便系统动画关闭，
内容仍然完整出现
页面仍然能够正常切换
不能因为动画 duration 为 0 导致 View 状态错误。

15. 本轮不要只“保留”原 OnboardingActivity
当前项目虽然已经存在：
OnboardingActivity.java
但本轮要求不是：
“原样保留即可”
而是：
请检查当前 OnboardingActivity 的实际实现，并按照以上要求完善成正式的首次启动动画使用引导。
如果已有的：
首次启动判断
跳过
下一步
完成状态
可以复用，就不要重写业务逻辑。
重点重构：
视觉
页面内容
动画
与新首页设计统一

十六、动画引导验收标准
本轮最终自检必须额外确认：
首次安装打开时先进入动画引导
非首次启动直接进入 MainActivity
至少有 4 个明确的引导场景
第一幕有通知逐条进入动画
第二幕体现消息重要性智能判断
第三幕体现消息进入不同文件夹的分流动画
第四幕展示最终首页并出现“开始使用”
页与页之间不是硬切
有下一步
有跳过
有进度指示
“我的 → 使用引导”可以重新观看
从“我的”重看不会破坏首次启动状态
所有动画使用原生 Android 能力或项目已有依赖
不额外引入大型动画框架
不依赖互联网素材
动画结束后的 View 状态正确
快速连续点击不会崩溃或页面错乱
Android 返回键行为合理
引导结束可以正常进入 MainActivity
Gradle 编译成功
另外，再在你原来最后的 「最终验收标准」 里补一个一级模块：
首次使用体验
第一次打开不是直接进入首页，而是先进入动画使用引导
动画引导与正式 App 的文件夹、纸张、消息气泡视觉统一
能通过动画看懂“收到通知 → 智能判断 → 自动分流 → 集中查看”的核心逻辑
引导结束后自然过渡到新首页
第二次启动不再强制播放
“我的 → 使用引导”可以随时重新播放
我还建议你在整份提示词最开头那句任务描述里也加一句，防止它做到最后又把 onboarding 当次要功能漏掉：
本轮不仅要完成四页主界面重构，还必须同步完成首次启动动画使用引导。动画引导属于本轮正式交付内容，不是后续优化项，不允许只预留入口或留 TODO。
