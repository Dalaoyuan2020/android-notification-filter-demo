## 核心演示实测

测试启动真正的 HTTPS 服务，只监听宿主 `127.0.0.1`，经 `adb reverse` 访问。三条路径分别为 `/official/v1/systemone`、`/bocha/v1/systemone`、`/relay/v1/systemone`，固定返回 `p_jev=0.7`。

临时 CA 和私钥生成在仓库外；仅 instrumentation 接收公开 CA，使用正常证书链及主机名校验。测试验证了系统默认信任拒绝该临时证书、测试专用信任接受该证书；没有关闭 TLS 校验、没有明文通道、没有将测试证书或私钥加入发布 APK，也没有访问真实模型服务。

发送器发出 410–414 五条淘宝样本；测试逐卡通过 SystemUI 的 `ACTION_DISMISS` 操作并等候真正的 `onNotificationRemoved`，五条均获得 `REASON_CANCEL=2, y=0.05`。没有直接调用记忆更新来替代用户行为链路。

| 探针 | 原始概率 | 融合概率 | 观察模式结果 |
|---|---:|---:|---|
| 420【淘宝】 | 0.700000 | 0.473432 | 保留卡片，显示下降箭头与清除建议 |
| 421【银行】 | 0.700000 | 0.700000 | 保留卡片，新前缀无历史，原值不变 |

随后打开自动清除、重发探针：淘宝融合概率约 `0.473532 < 0.5`，收到系统原因 `10` 和匹配的清除确认，银行仍在。自身清除的 `y=null`，淘宝观察数仍为 5，不会形成“自动删除越多、模型越想删”的反馈。

三路及两路 COMPARE 在自动开关被测试强制打开时仍保持通知；三路的原始概率、融合概率、耗时和结果均在同一屏幕内检查。截图前要求节点实际可见并完整落在屏幕内，而非仅检查离屏控件文本。

## 协议、保护与隐私

108 项 Android 模型检查覆盖生产 ModelClient 的 SystemOne 中文请求、阈值、概率与 choice 回退、非 JSON／非法概率、401／422 中文错误、429／529 精确最多三次尝试、超时、重定向拒绝及 Chat Completions 兼容。仿真错误连接不打开真实网络，不代表真实服务可用。

原有保护规则的 `DecisionEngine.java` 未修改。通知范围、保留词、持续／不可清除／分组汇总等保护顺序保留；旧通知更新、模型配置、规则或自动开关改变后，延迟的旧 REMOVE 不能删除当前卡片。相同 key 的新 postTime 会重置短时注意力的出现时间和忽略标记。

默认关键词、观察模式、模型联网关闭、事件上传关闭、正文上传关闭均检查通过。旧配置缺协议字段时仍按 Chat Completions 读取；注意力 Token 通过 Android Keystore 加密，填地址与 Token 不会自行打开上传。模型和注意力设置页禁止截屏，密码输入不进入实例状态。日志、记忆和设置不参与备份或设备迁移。

测试结束恢复关键词、远程关闭、空凭据、观察模式与默认规则。源码文件清单没有凭据文件、签名私钥或构建 APK；发布只包含用户安装的两个 APK，不发布 instrumentation 包或临时 CA。

## 发现并修正的问题

- 系统自动汇总可把最后一张演示通知记为分组连带移除。五张演示卡采用独立分组，复测五张均为真实 reason 2；未放宽学习规则。
- 旧 429 用例断言仅请求一次，与新版本的有限重试需求冲突；修正后明确验证 429／529 三次、其他错误一次。
- 同 ID 更新的旧计时、清日志与保存配置的锁顺序、移出目标范围后的行为学习已修正。
- 最初界面检查会读到离屏文本；补充完整屏内可见性断言并保存最终真实截图。

没有出现同一构建或测试错误连续三次仍无法解决的情况。
