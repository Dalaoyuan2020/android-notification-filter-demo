# 三分钟短时注意力演示

**后端 Jev 管长期判断，手机本地管短时注意力。** 本演示检查同一模型判断如何被近期真实操作修正：五条 `【淘宝】` 被手动划掉后，新的淘宝样本获得较低的本地注意力；同一个发送器里的新 `【银行】` 前缀不继承淘宝偏好。

“三分钟”指完成安装、授权和模型连接配置后的操作时间，实际网络等待可能更长。当前没有实体手机实测结论，也没有用真实凭据完成官方／自训服务联调；按本指南记录实际结果，不预填通过。

## 准备好再开始

1. 按[手机指南](PHONE_TESTING.md)安装两个 APK，筛选器开启通知使用权，发送器允许发送通知；确认监听“已连接”。
2. 把筛选器目标包名**仅设为** `com.example.notificationdemo.sender` 并保存，全程保持 **“自动清除”关闭**。
3. 按[模型指南](MODEL_TESTING.md)配置一个可用的 JEV 路线，完成固定合成连接测试后，选择该单路或多路对照，开启模型远程处理并保存。
4. 打开 **“短时注意力 · 行为与上传设置”**。先用默认半衰期 **30 分钟**、权重 **1**；独立事件上传及正文上传保持关闭。
5. 若要单独观察本地融合，把 **“JEV 请求附带近期行为摘要”关闭**并保存。这避免近期摘要同时改变后端的原始 `p_jev`；本地行为统计与融合仍继续工作。

半衰期默认 30 分钟便于演示。想在日常试验中更慢遗忘，可手动改为 **1440 分钟（一天）**，但两轮比较应使用同一参数并记录下来。

## 第 1 分钟：清理旧状态，发送五条样本

1. 在发送器点 **“清空本发送器的全部通知”**，移除旧测试卡片。
2. 回筛选器，在“验证记录”右侧点 **“清空”**。v0.3.0 这一步会同时清空日志、短时记忆和通知生命周期追踪；它不清理系统通知，所以要先做上一步。
3. 打开发送器，点 **“第一步 · 发送 5 条【淘宝】样本”**。对应 ID 为 **410、411、412、413、414**。
4. 下拉系统通知栏，必要时展开分组，**逐条手动划掉这五条通知**。

这里要真实的单条手势移除（系统 reason 2）。**不要点发送器清空按钮，不要用系统“全部清空”、整组划掉或筛选器自动清除代替。** 分组连带移除（例如 reason 12）也不会被当作单条划除偏好。演示样本分别使用独立分组，仍应逐卡操作并核对实际回调。

## 第 2 分钟：检查五次真实行为

回到筛选器的注意力页，点击 **“刷新注意力快照”**，找到 `【淘宝】` 条目。应观察到近期窗口内 **5 次划掉**，`p_short` 低于初始 `0.5`，有效证据 `n` 为正；具体小数会受到真实操作时间与衰减影响。

页面展示 `p_short` 最高和最低各 5 项。包级聚合与前缀条目可能同时出现；条目不足 10 项时两个榜单可以重叠。找准 `【淘宝】` 前缀，不要只看发送器的包级聚合。

如果划掉次数不是 5，先查看“验证记录”的移除原因，再记录手机型号和操作方式。不要手动改数据凑成 5，也不要把系统全部清空误计为五次划掉。

## 第 3 分钟：发送淘宝与银行探针

1. 在发送器点 **“第二步 · 发送【淘宝】+【银行】探针”**。
2. 新通知分别为 **420 `【淘宝】合成促销探针`**和 **421 `【银行】合成转账提醒`**。
3. 先不要点开或划掉它们，等待模型结果，再回筛选器看同一条记录中的 `p_jev → p_final`。

| 探针 | 关注点 |
|---|---|
| `【淘宝】` | 有五次划除形成的负向短时证据；通常在原始概率基础上向下修正 |
| `【银行】` | 新前缀没有历史，从 `(1,1)` 先验开始，有效 `n=0`；本地融合应完全保留本条的 `p_jev` |

判断的是**同一条记录里模型原始概率与本地融合概率的关系**。若开启近期行为摘要，后端原始 `p_jev` 本身也可能随摘要变化；不能把不同请求之间的所有变化都归因于手机融合。

箭头只在 `abs(p_final−p_jev)>0.05` 时显示 ↑／↓，否则显示 ＝；＝不等于数值完全相同。原始概率接近 0 或 1、证据衰减较多、模型只返回离散 choice 时，差异可能很小，并会受下述 logit 裁剪影响。**不要求任意真实模型都下降超过 0.05**；看证据、公式和方向是否一致，不把极值样本当作固定幅度验收。

项目的自动化隔离用例使用固定 mock `p_jev=0.7` 检查本地效果，不依赖真实模型随机输出。该用例是否通过及最终数值，见本次 Release 的验证记录；不能把 mock 结果写成真实服务或实体手机结果。

## 点击与忽略如何计分

演示后可以另发样本，再从系统通知栏点击它。通知通过真实 `PendingIntent` 打开发送器，系统产生点击移除回调；发送器不会伪造行为。

| 被观察到的行为 | 条件 | `y` |
|---|---|---|
| 快速点击 | 系统 `REASON_CLICK=1`，出现后 **≤60 秒** | `1.0` |
| 稍后点击 | 系统 `REASON_CLICK=1`，出现后 **>60 秒** | `0.7` |
| 单条手动划掉 | 系统 `REASON_CANCEL=2` | `0.05` |
| 放着不管 | 跟踪确认同一通知持续存在 **30 分钟**，本地计一次忽略 | `0.2` |
| 其他移除 | 系统全部清空、源 App 移除、监听器取消等 | 不训练 |

30 分钟忽略阈值是独立的固定阈值，不会随设置的半衰期变成 1440 分钟。短演示不会覆盖完整忽略等待、锁屏恢复或重启追踪；这些项目应另测。

## 公式与计数含义

每个来源／前缀的初始先验为 `alpha=1, beta=1`。距上次更新 `dt`，半衰期为 `h`，先衰减**原始 alpha 和 beta，包括先验部分**：

```text
lambda = 2^(-dt/h)
alpha  = lambda * alpha + y
beta   = lambda * beta + (1-y)
p_short = alpha / (alpha + beta)
n_raw   = alpha + beta - 2
n       = max(0, n_raw)
```

只读取快照而没有新行为时，仅执行时间衰减，不凭空添加 `y`。因为先验也衰减，`n_raw` 可以为负；它保留供实现与测试核验，页面显示非负的有效证据数 `n`。不能把 `n` 当作过去通知的实际条数。近期行为文字另按真实事件窗口计数，不用衰减值假装点击次数。

有证据时，融合为：

```text
p_final = sigmoid(logit(p_jev) + w * n/(n+3) * logit(p_short))
logit(p) = log(clamp(p, 0.01, 0.99) / (1-clamp(p, 0.01, 0.99)))
```

默认 `w=1`。**`n=0` 或 `w=0` 先直接返回原 `p_jev`，不经过 clamp，连 0 和 1 都完全保持。** 其他情况下 logit 输入会裁剪到 `[0.01,0.99]`，所以极值附近的最终数值不能按普通区间的差值解读。后验随时间衰减后，即使 `p_short` 比例仍偏向某一边，证据权重也会逐渐归零。

有 `【前缀】` 的通知只查询自身前缀记忆；无历史时使用先验，不回退到同包聚合。因此五次 `【淘宝】` 划掉不会给新 `【银行】` 前缀提供负向证据。

## 什么数据会离开手机

- **默认不发网络请求。** 关键词、自动清除关闭、远程模型关闭、独立事件上传关闭。
- 近期行为摘要选项默认开启；只有用户另行开启 JEV 模型远程处理后才随请求发出。摘要最多两条，来自当前目标 App 的真实窗口行为，可能含来源与前缀。
- 独立事件上传另有开关、HTTPS 地址与 Token，默认关闭。开启后发送来源、时间、移除原因、停留秒数、`y` 与概率等事件字段；正文默认不上传，需单独选择。
- 主界面“自动清除”只控制删除。若要停止网络处理，应关闭并保存相应的远程模型／独立上传开关；撤回通知使用权可停止后续读取。
