# 手机实测指南

这份指南供队友直接下载 APK，在自己的 Android 手机上验证通知读取与清除。无需 Android Studio、电脑连接或 Root。

**当前 v0.4.0 的界面入口与扫码下载，先看[三分钟体验指南](HACKATHON_DOWNLOAD.md)。** 下方保留历史版本与完整样本验收步骤；v0.4.0 的通知使用权、扫描与发送器入口位于“我的 → 通知权限”，模型配置位于“智能判断 → 模型配置”。

此前的通知流程只在 **Android 15 / API 35 的 AOSP 模拟器**完成验证；APK 的最低安装要求是 **Android 8.0 / API 26**，不代表所有版本和厂商手机都已测试。当前提供的是 debug 签名测试包。

- **v0.1.0：**纯关键词版，两个 App 都无网络权限、无模型调用。
- **v0.2.0：**增加兼容 Chat Completions 的官方／中转配置与双路观察对照；旧配置升级时保持原协议。
- **v0.3.0：**增加 TypeSafe Jev、Bocha Jev、自训中转三路配置和本地短时注意力。筛选器有网络权限，但默认关键词、远程模型关闭、自动清除关闭、独立事件上传及正文上传关闭；发送器仍不联网。官方地址和模型预设已明确，不含 API Key，尚未用真实凭据联调。配置见[三路模型指南](MODEL_TESTING.md)，新演示见[三分钟注意力指南](ATTENTION_DEMO.md)。

本页的“9 张样本 → 清除 2 张、保留 7 张”验收针对 **关键词策略**。v0.3.0 请先在“配置模型与三路对照”中选择“关键词”，关闭远程处理并保存；注意力页的独立事件上传也保持关闭，再做以下步骤。v0.2.0 的入口名称为“配置模型与双路对照”。

## 1. 下载并安装两个 App

1. 打开本仓库的 [最新 Release](https://github.com/Dalaoyuan2020/android-notification-filter-demo/releases/latest)，或从 [仓库主页](https://github.com/Dalaoyuan2020/android-notification-filter-demo) 进入 **Releases**，选择维护者指定的测试版本，展开 **Assets**。记录版本标签，避免两人使用不同版本比较结果。
2. 下载这两个附件，不要把 `Source code (zip)` 当成安装包：

   | 附件 | 安装后的名称 | 用途 |
   |---|---|---|
   | `notification-filter-demo.apk` | 通知筛选 Demo | 读取通知、匹配规则、请求清除 |
   | `notification-test-sender.apk` | 通知测试发送器 | 发送可控的合成通知样本 |

3. 在手机上分别打开 APK 安装。如果系统询问是否允许当前浏览器或文件管理器安装应用，仅为本次使用的安装来源开启对应权限；安装后可关闭。不同品牌的名称可能是“安装未知应用”或“允许来自此来源的应用”。
4. 两个 App 都安装完成后继续下一步。若安装被阻止，记录系统提示及手机型号，不要把“安装失败”记成通知筛选失败。

**此仓库已公开，无需协作者邀请即可浏览与下载。** 可直接打开[扫码下载页](https://attention-design-v040.rare-pixie-7903.chatgpt.site/download.html)，或在 Releases 下载两个 APK。看到 404 或找不到附件时，核对链接、版本标签和发布状态。

如出现“与现有软件包冲突”等覆盖安装错误，可能是签名不同。向维护者确认版本后，可先卸载旧测试包再安装；卸载会删除本机记录，筛选器需要重新授权。

## 2. 分别开启两种权限

| App | 要开启的权限 | 作用 |
|---|---|---|
| 通知筛选 Demo | 通知使用权／通知访问权限 | 读取其他 App 发布到系统的通知，并请求清除 |
| 通知测试发送器 | 允许发送通知 | 把测试样本放进系统通知栏；Android 13+ 对应 `POST_NOTIFICATIONS` |

1. 打开 **通知筛选 Demo**，点击 **“开启通知使用权”**。在系统列表中找到同名 App，开启通知访问。返回后应看到 **“已授权”** 和 **“已连接”**。
2. 如果系统提示受限设置无法开启，在系统 **设置 → 应用 → 通知筛选 Demo → 更多菜单** 中查找 **“允许受限制的设置”**，按系统提示操作，然后重新开启通知使用权。这适用于部分侧载安装和系统版本；若没有此入口，记录实际提示并反馈。参见 [Android 官方受限设置说明](https://support.google.com/android/answer/12623953?hl=zh-Hans)。
3. 点击 **“打开测试发送器”**，进入 **通知测试发送器**。点击 **“开启通知权限”**，允许发送通知；页面应显示 **“已允许发送测试通知”**。Android 8–12 可能没有同样的运行时弹窗，仍需确保系统未禁用该 App 的通知及“验收测试消息”渠道。

筛选器不需要发送通知权限；发送器不需要通知使用权。它们是两个独立 App，不能只装其中一个完成整套验收。

## 3. 先验证观察模式

首次安装默认关闭 **“自动清除”**。开关会保存，后续打开 App 或重启手机不会自动还原成观察模式，所以每轮测试前都要看一下。

1. 回到筛选器，确认 **“自动清除”关闭**，标签显示 **“观察模式”**。
2. 为先只测试合成样本，可将 **“目标 App 包名”**暂设为 `com.example.notificationdemo.sender`，点击 **“保存规则”**。保留默认关键词：
   - 保留：`紧急,会议,重要,家人`
   - 清除：`热搜,推荐,优惠,广告`

   出厂目标列表为 `com.sina.weibo,com.example.notificationdemo.sender`。若保留该列表，开启自动模式时微博也在规则作用范围内。微信 `com.tencent.mm` 默认不在目标列表。
3. 打开发送器，先点击 **“清空本发送器的全部通知”**，再点击 **“发送一组验收样本 · 9 张”**。
4. 等待约 5 秒，点击发送器的 **“刷新当前通知”**。应显示 **9 张**，ID 为：

   ```text
   [101, 102, 103, 104, 105, 200, 201, 202, 203]
   ```

5. 回到筛选器查看 **“验证记录”**：能看到发送器来源、标题、正文和原因；ID 102、202 对应的推荐优惠样本应得到 **“建议清除”**，但此时所有 9 个通知对象仍保留。

下拉通知栏可能把多张通知折叠成一组，屏幕上看到的行数不等于通知对象数。以发送器的当前 ID 列表配合筛选记录核对，也不要主动点开或划走样本，以免改变结果。

## 4. 再验证自动模式

1. 在发送器点击 **“清空本发送器的全部通知”**，刷新确认没有旧样本。
2. 回筛选器，开启 **“自动清除”**，标签应显示 **“自动模式”**。它会按已保存规则清除目标来源的通知卡片；已清除的卡片不能保证恢复。
3. 打开发送器，再点击 **“发送一组验收样本 · 9 张”**。
4. 等待约 5 秒，点击 **“刷新当前通知”**。预期只清除 **102、202**，保留以下 **7 个对象**：

   ```text
   [101, 103, 104, 105, 200, 201, 203]
   ```

| ID | 样本 | 自动模式预期 |
|---|---|---|
| 101 | 日常消息 | 保留，未命中清除词 |
| 102 | 推荐优惠 | 清除 |
| 103 | 紧急、会议，同时含优惠 | 保留，保留词优先 |
| 104 | 有标题、未提供正文 | 保留 |
| 105 | 含广告词的持续通知 | 跳过，持续通知受保护 |
| 200 | 消息分组汇总 | 跳过，避免连带清除整个分组 |
| 201 | 分组普通消息 | 保留 |
| 202 | 分组推荐优惠 | 清除 |
| 203 | 分组重要会议 | 保留 |

回筛选器核对两个广告的 **“已清除”**记录。**“请求清除”只表示已请求系统操作，不代表成功**；“未确认”需要和发送器当前 ID 列表一起报告。连续重发会产生多条处理记录，记录条数不等于当前通知数。

“自动清除”开关本身不会立即扫描所有旧通知。要主动验证已有通知，点击 **“重新扫描现有通知”**；监听服务重新连接时也会扫描当时的活动通知。观察模式下扫描只产生判断记录。

可选：分别点击发送器的 **“301 · 第一步：发送广告”**和 **“301 · 第二步：更新为紧急消息”**，每步等约 5 秒后刷新。自动模式应先清除广告，随后保留以同一 ID 发布的紧急消息。该测试会额外出现 ID 301，重新做 9 张验收前先清空发送器通知。

## 5. 微信、微博内容能读到多少

先关闭自动清除，使用自己控制的测试账号或请队友发送约定的合成文本，例如“测试消息 A：明天会议改期”。不要用真实聊天、验证码、账号密码或付款信息做样本。

微信默认不清除，但授权后可在筛选记录里观察系统实际提供的内容。记录以下情况即可，无需贴出真实正文：

- 来源 App 及版本；单聊、群聊或其他通知类型。
- 手机解锁／锁屏；来源 App 的通知预览是显示内容还是隐藏内容。
- 标题、发送人、正文分别为“可读／部分可读／隐藏／缺失”。
- 多条消息是多张独立卡片，还是被合并成一张。

如果来源 App 只提供“收到一条消息”，筛选器不能从该接口读取背后的完整聊天。Android 8–10 的结构化多消息通知会保守整卡保留。不要为了读到隐藏内容而把缺失结果改成“通过”。

## 6. 后台、熄屏和重启

每项都记录手机品牌型号、Android 版本、厂商系统版本、两个测试 App 版本和测试时间。先保持手机当前的省电设置；如果后来调整了后台运行或电池设置，分别记录调整前后结果。

| 场景 | 操作 | 记录重点 |
|---|---|---|
| 普通后台 | 筛选器已连接且自动模式开启，按 Home 离开；从桌面打开发送器，清空并重发 9 张样本 | 未返回筛选器前，发送器是否已只剩预期 7 个 ID |
| 熄屏后恢复 | 锁屏放置 5–10 分钟，解锁后先打开发送器，不先打开筛选器；重做 9 张验收 | 能否继续筛选；返回筛选器后是否仍连接 |
| 熄屏期间读取 | 关闭自动清除并保持授权；锁屏后由另一台设备发送约定的合成微信消息；稍后解锁查记录 | 是否记录到锁屏期间发布的消息，以及内容是否被隐藏 |
| 手机重启 | 确认测试配置后重启并解锁；先打开发送器，重做 9 张验收，再检查筛选器 | 自动模式设置是否保留、监听是否恢复、是否需要手动打开筛选器或重新授权 |

发送器当前需要点按钮发样本，没有“锁屏定时发送”功能。“熄屏后恢复”不等于已证明“熄屏期间自动清除”；后一项若没有真正收到新样本，填“未测试”。微信默认不在目标列表，因此锁屏合成微信消息只验证读取，不验证自动删除。

若结果异常，先记录现象，再尝试打开筛选器检查“已授权／已连接”。必要时在系统设置中关闭后重新开启通知使用权，并记录恢复方法。不要把手动恢复后的结果写成始终稳定运行。

## 7. 暂停、结束与撤回权限

- **暂停自动删除：**关闭筛选器的“自动清除”。之后仍可读取和记录通知；已向系统提交的请求可能完成，关闭开关也不会恢复已清除卡片。
- **停止通知访问：**点击“开启通知使用权”进入系统列表，把 **通知筛选 Demo** 的访问开关关闭。返回应不再显示已授权／已连接；新样本不应继续被筛选器读取或清除。
- **清理测试样本：**在发送器点击“清空本发送器的全部通知”。v0.3.0 筛选器“验证记录”右侧的 **“清空”**会清空本机日志、短时记忆与生命周期追踪，不清理系统通知。重做注意力演示时，先清发送器通知，再清筛选器记录。
- **完整结束：**关闭自动清除，关闭并保存不再需要的模型远程处理和独立事件上传开关，撤回通知使用权；按需清空记录并卸载两个测试 App。系统里也可关闭发送器的发送通知权限。

清除通知卡片不等于删除来源 App 内的聊天消息；此 Demo 也不能保证通知发布时的声音、振动或横幅被阻止。

## 8. 把结果反馈到 GitHub

进入本仓库的 [新建 Issue 页面](https://github.com/Dalaoyuan2020/android-notification-filter-demo/issues/new/choose)，选择 **“手机实测反馈”**，填写结构化表单。私有仓库中同样不要提交真实消息正文、联系人、群名、手机号、验证码、Token 或账号密码。截图只展示发送器的合成样本；通知栏若混有私人信息，先裁剪或遮盖再上传。

没有做完的项目填“未测试”，遇到权限或安装阻断填实际原因，不要推测成功。最少提供：

```text
Release 标签：
手机品牌 / 型号：
Android / 厂商系统版本：
筛选器 / 发送器版本：
目标包名、保留词、清除词是否改过：
通知使用权与监听连接：
观察模式：当前 ID 列表；是否出现建议清除：
自动模式：当前 ID 列表；两张广告是否出现已清除：
后台 / 熄屏后 / 熄屏期间 / 重启：逐项写通过、失败或未测试：
微信 / 微博版本与字段可读性（不贴真实正文）：
异常复现步骤与恢复方式：
```

反馈用途是确认不同手机上的真实边界，不代表已经通过全部兼容性、长期稳定性或应用商店上架验证。
