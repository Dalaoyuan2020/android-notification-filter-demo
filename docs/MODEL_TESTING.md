# 三路模型配置与对照

适用于 **v0.3.0**。TypeSafe Jev、Bocha Jev 和自训中转分别配置；模型负责内容判断，手机以本地短时行为融合保留概率。本页说明已经实现的协议与按钮，**不表示已用真实 API Key 接通服务，也不表示实体手机已通过验证**。

首次安装见[手机指南](PHONE_TESTING.md)；概率融合与操作演示见[注意力演示](ATTENTION_DEMO.md)；改代码见[开发指南](../CONTRIBUTING.md)。

## 1. 配置之前

1. 开启筛选器的通知使用权与发送器的发送权限，确认筛选器“已授权／已连接”。
2. 关闭主界面的“自动清除”，把目标包名设为 `com.example.notificationdemo.sender` 并点击“保存规则”。
3. 点击 **“配置模型与三路对照”**。先保持 **“允许远程处理目标通知”关闭**，填写配置并进行合成连接测试。

模型远程开关默认关闭；模型策略下不开远程会保留通知，不回退到关键词清除。保存模型配置或注意力参数都会关闭自动清除。只关闭“自动清除”不能停止模型观察请求。

## 2. 三条路线与升级行为

| 编辑按钮 | 新安装预设地址 | 模型 ID | 默认协议 |
|---|---|---|---|
| TypeSafe | `https://api.typesafe.ai` | `jev-latest` | JEV SystemOne |
| Bocha | `https://jev.bocha.cn` | `bocha-jev-v1` | JEV SystemOne |
| 自训中转 | 留空，填实际部署地址 | 留空，填部署支持的模型 | JEV SystemOne |

所有路线都不预填密钥。TypeSafe 和 Bocha 的名称、地址及协议已明确；自训中转还需要实际部署地址和凭据。预设不代表服务在线、账号有额度或模型调用已成功。

已有 v0.2.0 配置升级后保留原字段及 **Chat Completions** 协议，避免改变已有服务调用。若要改用 JEV，选择相应路线并点击 **“载入当前路线预设 · 保留密钥”**，核对后保存。自训中转没有固定部署地址，该按钮会提示自行填写，不会猜测地址。

| 字段 | 填写说明 |
|---|---|
| 接口协议 | 按服务选择 `JEV SystemOne` 或 `Chat Completions`，不能只换模型 ID 而忽略协议 |
| 配置标签 / 版本标识 | 用于结果卡片和实验记录，例如部署版本；不放密钥 |
| 接口地址 · HTTPS | 可访问的服务地址，不含账号密码、查询参数或片段 |
| 模型 ID | 使用服务实际支持的精确标识 |
| API Key | 服务的 Bearer 密钥；无需鉴权的自训端点可留空 |
| 保留阈值 | `0–1`，默认 `0.5`；`p_final >= 阈值` 时保留 |

手机的 `localhost` 或 `127.0.0.1` 指手机自身。自建接口需要手机能访问的 HTTPS 地址与受信任证书；不支持明文 HTTP，不绕过证书验证，不自动跟随重定向。

点击 **“保存配置并关闭自动清除”**后才生效。API Key 由 Android Keystore 加密保存，密码框不写入页面恢复状态。未保存的编辑在离开或旋转屏幕后丢弃；卸载或清除数据后需要重新配置。

## 3. 先做单路合成连接测试

选择上方一个编辑按钮，保存后点击 **“仅测试当前配置（合成消息）”**。有未保存修改时不会发请求。每次只测当前路线，不同时请求三路。

**这个按钮即使在模型远程开关关闭时也会发送固定合成消息。** 远程开关管理通知处理；连接测试是单独的明确操作，不读取真实通知栏。

```text
包名：com.example.notificationdemo.synthetic
标题：连接测试：合成通知
正文：这是一条用于验证模型接口的合成通知，不包含真实用户消息。请保留此通知。
```

界面显示概率、判断、原因及耗时。协议测试成功只证明本次响应可被解析，不保证模型判断正确。没有概率的 choice 回退结果会明确标注。失败时记录错误码和安全中文说明，例如 401 的鉴权问题、422 的请求格式问题；不要上传原始响应、密钥或带凭据的地址。

## 4. JEV SystemOne 协议

JEV 路线向 `POST /v1/systemone` 发送请求。地址支持根地址、以 `/v1` 结尾的基础地址，或完整 `/v1/systemone` 端点：客户端只补所缺的这段路径。

请求使用服务支持的 `model`；`state` 的中文字段为“来源”“标题”“消息”。允许近期行为摘要时增加“近期行为”。固定 choice 问题为：

```json
{
  "model": "由当前配置指定",
  "state": {
    "来源": "通知测试发送器",
    "标题": "【淘宝】合成促销探针",
    "消息": "一条合成测试通知"
  },
  "questions": {
    "keep": {
      "type": "choice",
      "instructions": "这条通知是重要的个人通知，还是广告营销？",
      "criteria": {
        "重要": "重要的个人通知",
        "广告": "广告、营销或垃圾信息"
      }
    }
  }
}
```

从 `answers.keep.probabilities["重要"]` 读取 `[0,1]` 内的原始保留概率。只有 `probabilities` 字段缺失，或该对象里缺少“重要”键时，才允许按合法 `choice` 回退：`重要` 映射为 1、`广告` 映射为 0，并标记“无原始概率”。已经存在的概率字段若为 null、错误类型、越界或非有限数值，即使同时有合法 choice 也按失败处理，保留通知。

官方协议资料：[TypeSafe OpenAPI](https://api.typesafe.ai/openapi.json)、[TypeSafe Swagger](https://api.typesafe.ai/docs)、[Bocha 官方接口说明](https://jev.bocha.cn/install/bocha-jev/SKILL.md)。公开文档核验与携带密钥的实际联调是两件事；本项目没有据此宣称真实调用成功。

## 5. Chat Completions 兼容路线

这是保留的旧协议适配器。去掉基础地址末尾 `/` 后附加 `/chat/completions`；已有完整该路径则直接使用，**不会自动补 `/v1`**。

- 请求包含 `model`、`messages`、`stream: false`、`response_format: {"type":"json_object"}`；通知数据为 `package/title/text/category`，不附带 JEV 的近期行为字段。
- 响应需为 `application/json`，`choices` 恰一项，`finish_reason=stop`，消息角色为 `assistant`，不含工具调用或拒绝消息。
- `message.content` 为严格 JSON 字符串，仅含 `action` 与 `reason`：动作是 `KEEP` 或 `REMOVE`，理由非空且不超过 240 字符。
- 该协议返回离散动作，没有原始 JEV 概率；界面会标记概率来源，不能把动作映射值当成校准后的置信度。

两种协议都只走 HTTPS，密钥通过 `Authorization: Bearer` 发送。连接超时 6 秒、读取超时 8 秒；429／529 最多重试两次，分别退避 500／1000 毫秒，**所有尝试共享 15 秒总预算**。请求上限 64 KiB、响应上限 32 KiB；完整输入过长时保留，不截断发送。

## 6. 三路对照与单路处理

1. 分别完成准备参与对照的路线的合成连接测试。
2. 选择 **“多路对照 · 只观察，不清除”**，勾选 TypeSafe、Bocha、自训中转中的可用路线，最多三路。
3. 开启“允许远程处理目标通知”并保存，回主界面确认“对照观察”、自动清除不可用。
4. 在发送器清空旧样本，再发“发送一组验收样本 · 9 张”。
5. 模型返回后查看横向结果卡片：配置标签、模型／协议、`p_jev → p_final`、耗时、判断、失败原因及路线结论是否一致。

新安装默认勾选 TypeSafe 与 Bocha；升级旧对照配置保留官方与中转的参与设置。只选一路可检查该路线，但不能据此比较不同模型。任一路失败要如实记录，不能计作一致。

对照模式下 9 个通知对象都应保留：`101,102,103,104,105,200,201,202,203`。默认保护规则通常仅让 101、102、201、202 进入模型，其余由保留词、空正文、持续或汇总保护跳过。横向卡片箭头只在 `abs(p_final−p_jev)>0.05` 时显示 ↑／↓；其他显示 ＝，不表示两数完全相同。

需要试单路删除时，选择 TypeSafe、Bocha 或自训中转单路，保存后先观察，再手动开启自动清除。实际结果由融合概率和阈值决定，不应套用“必删 102、202”的关键词验收结论。“请求清除”仍需系统回调和当前 ID 列表确认。

## 7. 注意力、上传与停止

“JEV 请求附带近期行为摘要”默认开启，选取当前目标 App 变化最大的至多两条真实摘要，包含来源或标题前缀。它本身不会打开远程模型。要隔离本地融合因素，可关闭该摘要后保存；公式与实操见[注意力演示](ATTENTION_DEMO.md)。

独立事件上传在注意力页单独设置，默认关闭，正文默认不上传。这不是模型 API Key 配置，也不会随启用模型自动开启。测试结束时，关闭并保存模型远程开关及需要停止的独立上传开关；已发出的数据无法收回。撤回通知使用权可停止后续读取。

4080 注意力服务接收 `POST {基础地址}/events`，使用 JSON 和 `Authorization: Bearer {Token}`（Token 留空则不发送此头）；输入已以 `/events` 结尾时不重复追加。字段为 `包名`、`App名`、`出现时间`、`消失时间`、`事件时间`、`原因`、`reason_code`、`停留秒数`、`y`、`p_jev`、`p_final`。时间为 Unix 毫秒；仍活跃的忽略事件 `消失时间=null`，未获得模型判断的概率为 null，其他移除的 `y=null`。对照模式的事件概率取第一条已选择路线（顺序 TypeSafe、Bocha、自建）；完整三路结果保留在本机模型日志。只有另开正文上传才增加 `正文` 字段。上传独立运行，失败丢弃、不重试、不影响通知判断；本版尚未联调实际 4080 展示板。

到 [Issue 入口](https://github.com/Dalaoyuan2020/android-notification-filter-demo/issues/new/choose) 选择模型反馈，记录版本、手机、路线、协议、模型 ID、摘要开关、阈值、半衰期、权重、概率和实际通知状态。仅使用合成消息，不提交密钥、验证码或真实私人正文。没有做的项目写“未测试”。

当前缺少 `attention_suite_v1.jsonl`，`suite_s1` 跳过；v0.4 评测页面尚未实现，不能将手动演示当成完整模型评测。
